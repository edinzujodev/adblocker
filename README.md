"Jok" means "no" in Bosnian, and that is the job: JoK says no to ads,
trackers and the sites you choose, for every device in your home.

JoK is a home ad blocker in the style of Pi-hole: a small DNS server that answers
ad/tracker domains with `0.0.0.0` / `::` and forwards everything else to an
upstream resolver. It is a single Go binary, built to run on a Windows PC for
development and on a Raspberry Pi 3 Model B+ (linux/arm64) later.

## Layout

```
cmd/adblocker/         main program (flags, startup)
internal/blocklist/    hosts-format list parsing + domain matching
internal/filter/       block decision: lists + your own blocks/allows + on/off
internal/groups/       block groups: built-in categories and your own groups
internal/querylog/     recent queries and counters for the web interface
internal/dnsserver/    DNS handler: block or forward, query logging
internal/web/          web interface: JSON API, serves the embedded web app
internal/web/dist/     built web app (generated by `npm run build`, committed)
web/                   web app source: React + TypeScript + Vite + shadcn/ui
mobile/                Android/iOS app: Expo + NativeWind + react-native-reusables
packages/api/          TypeScript API client shared by web/ and mobile/
```

## Requirements

- Go 1.27+ (`go version`)
- Node.js 22+ only if you change the web interface (`web/`)

## Run

```powershell
go run ./cmd/adblocker
```

Defaults: listens on `127.0.0.1:53` (UDP + TCP), forwards to `1.1.1.1:53`,
blocks the StevenBlack unified hosts list
(`https://raw.githubusercontent.com/StevenBlack/hosts/master/hosts`).

Flags:

| Flag | Default | Meaning |
|------|---------|---------|
| `-listen` | `127.0.0.1:53` | Address to listen on. Use `:53` to serve the whole LAN, or e.g. `127.0.0.1:15353` for testing. |
| `-upstream` | `1.1.1.1:53` | Resolver allowed queries are forwarded to. |
| `-blocklist` | StevenBlack hosts | File path or http(s) URL in hosts format. Repeat the flag (or comma-separate) for several lists. |
| `-custom` | `custom-blocklist.txt` | Your own blocked sites. Edited from the web interface; don't also pass it to `-blocklist`. |
| `-allowlist` | `allowlist.txt` | Sites that are never blocked. Edited from the web interface. |
| `-groups` | `groups.json` | Which categories are on, and your own block groups. Edited from the web interface. |
| `-web` | `:8080` | Web interface address. `:8080` is reachable from your phone; `""` turns it off. |
| `-password` | `$ADBLOCKER_PASSWORD` | Sets the web password at every start. Leave it unset so the password can be changed in Settings. |
| `-password-file` | `admin-password.txt` | Where the first, generated password is shown. Deleted once the password is changed. |
| `-auth` | `auth.json` | Holds the web password's hash (never the password itself). |

Examples:

```powershell
go run ./cmd/adblocker -listen 127.0.0.1:15353
go run ./cmd/adblocker -blocklist my-hosts.txt -blocklist https://example.org/hosts
```

Every query is logged as `BLOCKED` or `ALLOWED` with client IP, type and name.

Note: on Windows, port 5353 is taken by mDNS, and `nslookup` ignores
`-port=`, so test on port 53 with `nslookup doubleclick.net 127.0.0.1`.

## Web interface

On startup the server prints the web addresses and the password:

```
web interface: http://localhost:8080
  on your phone (same Wi-Fi): http://192.168.0.23:8080
web password: k7mxq2vbtr (also in admin-password.txt until you change it in Settings)
```

Open the phone address in your phone's browser and log in. The interface has
four tabs:

- **Home**: blocking on/off switch, a "protect this computer" switch, query
  counters, and a "test a site" box that says whether a domain is blocked
  and why.
- **Activity**: recently blocked domains (with an Allow button) and the most
  blocked domains.
- **Groups**: block whole categories with one switch (social media, video &
  streaming, gaming, messaging, shopping, dating, gambling, adult, fake news),
  and make your own groups of sites and keywords to switch on and off
  together. The first six categories are built in; gambling, adult and fake
  news use StevenBlack's maintained lists, downloaded when switched on and
  again at startup. The always-allowed list wins over groups. **Bundles**
  put several groups (categories and your own) under one switch, like "Kids
  mode": while a bundle is on, all its groups block; switching it off leaves
  each group's own switch as it was.
- **Lists**: your own blocked sites and always-allowed sites. Changes take
  effect immediately, no restart needed. A pasted URL such as
  `https://www.instagram.com/` is stored as `instagram.com`, which covers all
  subdomains. A word without a dot is a keyword: `instagram` blocks every
  domain containing it (`instagram.com`, `cdninstagram.com`, `instagram.de`,
  ...). Keywords need at least 4 letters or digits, and the allowlist still
  wins over them.

**Protect this computer** (Windows only) points the DNS of every connected
network adapter at JoK, or back to automatic. Windows only allows
this for programs started **as administrator** (right-click PowerShell, *Run
as administrator*, then start JoK there); otherwise the switch is
greyed out.

It never cuts the computer off the internet:

- **Backup DNS.** The network's own DNS server (usually the router) stays
  configured behind JoK. If JoK is not running for any
  reason (crash, killed in Task Manager, laptop on another Wi-Fi), Windows
  gets no answer from it and immediately uses the backup. Ads get through,
  but pages load.
- **Cleanup.** Switching protection off, or stopping JoK (Ctrl+C or
  closing its window), puts DNS back to automatic, including the settings
  Windows saved for Wi-Fi networks the computer is not connected to now.

Windows asks whether to allow the program through the firewall the first
time; allow it on **private** networks, or your phone can't connect. Because
`go run` builds to a new temporary path each time, build once and run the
binary instead so the firewall rule sticks:

```powershell
go build -o bin/adblocker.exe ./cmd/adblocker
.\bin\adblocker.exe
```

### Changing the web interface

The web app lives in `web/` (React, TypeScript, Tailwind CSS, shadcn/ui).
Run the Go server, then in another terminal:

```powershell
cd web
npm install
npm run dev     # http://localhost:5173 with hot reload, API proxied to :8080
```

When done, `npm run build` writes the production build to
`internal/web/dist/`; rebuild the Go binary to embed it. Commit both.

## Passwords

- **The password** is what everyone logs in with. It can be changed in
  **Settings** (the current password is needed; other devices are signed
  out). Only a PBKDF2 hash is stored, in `auth.json`.
- **The master password** is a recovery key built into the program. Logging
  in with it only opens a "Set a new password" screen. It can't be changed
  from the web interface or the app, only by rebuilding:

  ```powershell
  go run ./cmd/masterpw          # asks for it twice, writes internal/auth/keys/master.hash
  go build -o bin/adblocker.exe ./cmd/adblocker
  ```

  `master.hash` holds only a hash and is git-ignored, so it is never
  committed: keep your own backup of the master password. Every copy of that
  build accepts the same master password, so use a long random passphrase
  (at least 16 characters). Without `master.hash` there is no master
  password.
- **Never commit secrets.** `admin-password.txt`, `auth.json`, `master.hash`
  and `.env` files are git-ignored. For a second check, install the
  pre-commit hook once: `cp scripts/pre-commit .git/hooks/pre-commit`. It
  stops commits that contain those files, a password hash, or the current
  password.

### API

The web app and the mobile app use a JSON API.
`POST /api/login` with `{"password": "..."}` returns `{"token": "..."}` and
sets a session cookie; send either the cookie or `Authorization: Bearer
<token>` on the other calls. With the master password it returns
`{"reset": true, "resetToken": "..."}` instead and no session.

| Method | Path | Body / query | Result |
|--------|------|--------------|--------|
| `POST` | `/api/password` | `{"current": "...", "password": "..."}` | change the password; other sessions end |
| `POST` | `/api/password/reset` | `{"resetToken": "...", "password": "..."}` | after a master login, no session needed; all sessions end |
| `GET` | `/api/status` | | `enabled`, `totalQueries`, `blockedQueries`, `blocklistSize`, `customCount`, `allowCount` |
| `POST` | `/api/enabled` | `{"enabled": false}` | switches blocking on/off |
| `GET` | `/api/queries` | `?blocked=true&limit=100` | recent queries, newest first |
| `GET` | `/api/top-blocked` | | 20 most blocked domains |
| `GET` | `/api/check` | `?domain=instagram.com` | `blocked`, `reason`, `rule` |
| `GET` / `POST` | `/api/custom` | `{"domain": "..."}` | list / add your blocked sites |
| `DELETE` | `/api/custom/{domain}` | | remove one |
| `GET` / `POST` | `/api/allowlist` | `{"domain": "..."}` | list / add allowed sites |
| `DELETE` | `/api/allowlist/{domain}` | | remove one |
| `GET` | `/api/groups` | | categories and your groups |
| `POST` | `/api/groups` | `{"name": "...", "entries": [...]}` | create a group |
| `PATCH` | `/api/groups/{id}` | `{"enabled": true}` and/or `{"name": "..."}` | switch on/off, rename |
| `DELETE` | `/api/groups/{id}` | | delete one of your groups |
| `POST` | `/api/groups/{id}/entries` | `{"domain": "..."}` | add a site or keyword to your group |
| `DELETE` | `/api/groups/{id}/entries/{entry}` | | remove one |
| `GET` | `/api/bundles` | | your bundles |
| `POST` | `/api/bundles` | `{"name": "...", "groups": [...]}` | create a bundle (off) |
| `PATCH` | `/api/bundles/{id}` | `{"enabled": true}` and/or `{"name": "..."}` | switch on/off, rename |
| `PUT` | `/api/bundles/{id}/groups` | `{"groups": [...]}` | set which groups it holds |
| `DELETE` | `/api/bundles/{id}` | | delete a bundle |
| `POST` | `/api/logout` | | ends the session |

## Use it as this PC's DNS (Windows)

Start the server first, then in an **administrator** PowerShell:

```powershell
Get-NetAdapter | Where-Object Status -eq Up          # find your adapter name, e.g. "Wi-Fi"
Set-DnsClientServerAddress -InterfaceAlias "Wi-Fi" -ServerAddresses 127.0.0.1
Clear-DnsClientCache
```

Undo (back to the DNS your router hands out via DHCP):

```powershell
Set-DnsClientServerAddress -InterfaceAlias "Wi-Fi" -ResetServerAddresses
Clear-DnsClientCache
```

While the PC points at `127.0.0.1`, the adblocker must be running, or name
resolution stops. Browsers with "secure DNS" (DNS-over-HTTPS) enabled skip
it, so turn that off in the browser to see blocking.
